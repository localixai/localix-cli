# LAYOUT.md

The map of every file: what each module holds, and the rule it serves. ARCHITECTURE.md says where a
thing goes and what may know what, and AGENTS.md has the rules, the tests and the checks; this says
what is already there. Read the part for the package you are about to change, and change its line
in the same change when a file is added, moved, removed or given another job.

Packages and three apps: the server (the composition root), the interface and the binary. Every dependency points inward (rules L1-L5, AGENTS.md).

- `packages/contracts`: ports only, no logic.
  - `chat.rs`: the chat-model port, with our own `Message` (`said`: the person's words, from which the providers' session and cache keys are hashed), `ToolCall`, `Request` (with the `deadline` the caller still wants an answer by, the conversation's own `effort`, taken where the model offers it: `Selection::or_at`, and its `task`: a `TaskId` the agent gives each task, never twice in a process, `TaskId::NONE` for a one-off request), `Completion` (its `Ending`: whole, or cut off at the output limit; its `thought`, the reasoning as text where the host gives it so), `Usage` and `Spend` (usages summed: the chat model's in a run, the decision model's in `llx decide`).
  - `catalog.rs`: what a provider offers: `ModelEntry` (an id, a name, the `Effort` levels it takes, its default; `Effort::wire_name`, the spelling both providers send) and `Selection`, a model with a level it takes (its fields are private: no other level can be put in).
  - `tool.rs`: the agent's tools: `ToolSpec` (a name, a description, its `Input`: arguments' JSON Schema, or the Lark grammar of a text tool), `ToolOutput { report, shown }` (`shown`: what only the person reads, an edit's diff, never sent to the model), `ToolError { Failed, Fatal }`; `Tool::salvage`, what of a call the output limit cut off is whole (B7: `None` by default, and the call is not run).
  - `advice.rs`: the advisor port (C9): `Task` (the goal, the conversation, where the task starts), `Review { Done, GoOn(line) }`, `Advisor` (`level`, asked only as a conversation's first task starts; `review`).
  - `gate.rs`: a tool asks before an effect: `Effect { tool, subject, summary, needs }` (`Needs { Sandbox, Open }`: whether it must leave its sandbox, B6), `Verdict { Allow, Workspace, ReadOnly, Deny(why) }` (`Workspace`: run where it can change only the workspace; `ReadOnly`: where it can change nothing), `Gate`, and `Open`.
  - `person.rs`: a tool asks the person: `Question` with its `Choice`s, `Answer`, `Reply { Answers, Nobody(why), Stopped }`, `Person`.
  - `model.rs`: the decision-model port: typed questions, `Decider` (`llx decide`).
  - `history.rs`: sessions, `History` (`start`, `load`, `list`, and `hold`: a session's one writer, a `Record`, K8), whose errors are `HistoryError` (`Held`: another has its writer).
  - `inbox.rs`: what reaches a run between its turns, `Inbox`.
  - `shape.rs`: `--schema`'s port (ARCHITECTURE.md P8): `Shape`, the schema the model is told and every way data does not match it; the app builds it from flowschema.
- `packages/agent`: the agent.
  - `agent.rs`: the loop: a turn's calls (those that may, at once: `calls.rs`), the inbox between turns, the stop conditions: a task ends with the model's message with no call, as Codex's does (one the output limit cut off is not one: the model goes on from it, what it thought kept as its words when it said nothing, a fourth cut in a row an error); nothing invites it to stop (an answer while an agent's answer or a job is still to come waits for it, its words shown as the wait begins; when nothing comes they are the answer, already shown: `Run::shown`, and the interface is not sent it again); with `--schema`, `result` is offered with every request (the tools never change, so the prompt cache holds), a `result` call alone with matching data is the answer too, and an answer in words is followed by one more request with the call forced (`schema.rs`; `agent/returned.rs`: a `result` beside other calls not taken, one before what is still to come made to wait, a mismatch sent back twice at most; the data's request after an answer in words, the call forced only where the host takes that, any other call answered unrun, words asked again). `Agent::run` reaches a goal in a new conversation or one that goes on (an `Option`), with the pictures attached. `Agent::context` is the app's environment block, sent before the first goal; `Agent::tell` is what the app says between goals (a changed mode), naming no tool. `agent/handling.rs`: a turn's calls carried out and answered; the last call of a reply the output limit cut off goes to `Tool::salvage` when its tool takes its arguments' shape, else is answered unrun (B7), and a cut reply that did nothing counts toward the cuts in a row. `agent/advice.rs`: the advisor's word (C9): a fresh conversation's level (kept in the `Conversation`, so a follow-up and a fork keep it); a line after an answer it finds unfinished, twice a task at most, never on the last turn.
  - `observer.rs`: what a run shows as it goes: calls, results, turns.
  - `conversation.rs`: messages that only grow. Open calls are closed; `truncate` for a rewind. A picture stays only when the person attached it.
  - `history.rs`: how a conversation is prepared before each request, a `Strategy` the app chooses (it uses `Pipeline`: stages `reasoning` (old turns' reasoning, as the provider's `Shed` lets it go: `providers::shed`, OpenAI's sealed items and Anthropic's thinking blocks), `outputs`, `arguments`, behind a 90%→40% gate of llx's ceiling (`Limits`: the ceiling, at most 272k, and the model's own limit), a pass that could not reach 40% opening again only once the conversation grew 50% of the ceiling past where it left it, a protected tail that gives way only past the model's own limit, the newest output of each call the app keeps (`Lasting`: the server's, an instruction file read) left alone as the tail is, elisions that stay: made for the prompt cache; what a turn carries back is counted, and another model's let go as the model changes: `Conversation::for_model`). `history_tests.rs` simulates a 300-turn dialogue.
  - `schema.rs`: the `result` call of `--schema`: `data` matching the schema, offered with every request, asked for after an answer in words with the call forced, checked through the `Shape` port, a mismatch sent back (twice at most once asked for).
  - `prompt.md`: the system prompt.
  - `fakes.rs`: test-only fakes: a scripted chat, an echo tool, a recorder, and `Keep`, the history strategy that sends a conversation as it is.
- `packages/tools`: the tools, a module each.
  - `workspace.rs`: where paths resolve. A file can be read anywhere but the paths the app denies (its config directory with the keys and tokens, its sessions). A path to change is followed through its symlinks to where it really is (`writable`); a path to delete is followed in all but its last name (`removable`), so a link deleted is the link itself. Its commands run with the environment it is given (`with_env`).
  - `fs/`: `patch.rs` with `patch/` (`apply_patch`: `tool.rs` the tool and its grammar, `run.rs` every file worked out and asked of the gate before any is written, a read-only verdict refused, `disk.rs` the files as the patch found them and leaves them (each read the first time the patch names it and again before the write, then all written or every one put back; a symlink it deletes or moves is the link itself, never what it points at (a move's new file holds what was read through it, checked unchanged before the write), and a file it adds under that name takes the link's place), `cut.rs` a patch the output limit cut off: the files before the one the cut fell in, applied as a patch of their own (B7), `apply.rs` and `seek.rs` a hunk found by its lines and those around it, else the file given back: whole and numbered when it is short, its nearest lines when it is long), `atomic.rs` (a write as a temporary file renamed, its permissions kept; a read-only file refused, one with other hard links written in place), `diff.rs` (what a patch's edits did, as `patch/apply.rs` records them, rendered for the person), `picture.rs` (the one reader of PNG, JPEG, GIF and WebP: known by their signature, measured from their header, as a model takes them; the app's attachments).
  - `shell/`: `bash.rs` (the tool), `running.rs` (`Running`: a command started, its output read as it comes, waited for by whoever holds it, killed with all it started when let go), `background.rs` (B9: a command waited for 120 s at most, then handed to the session's jobs through the `Background` trait the app implements; `run_in_background` hands it at once; a `sleep` killed at its wait; what the model reads of it), `sandbox.rs` (`Scope { Open, Workspace, ReadOnly }`, from a gate's verdict by `Scope::of`; `permit`, which asks again as `Needs::Open` a workspace verdict where no sandbox can be set up: a confined command (B3) in the system's sandbox with a scratch `$TMPDIR` of its own, removed after, that writes the workspace but its `.git` (on macOS no `.git` at all, a nested repository's or a new one, in any case) in the workspace's scope (read-only where the workspace is the home or holds it, and on Linux, where Landlock could keep no `.git` in it from the command); a read-only one refused where none can be set up; `refused`, whether a failure looks like the sandbox's, which `bash` then says) with `sandbox/macos.rs` (Seatbelt: `sandbox-exec` with a profile closed by default) and `sandbox/linux.rs` (Landlock and a seccomp filter that refuses every socket, set between fork and exec after `no_new_privs`), `process.rs` (`scoped`: the command ready to start, with the variables a command runs with (the workspace's, else the process's, less the hidden ones), then under `Quiet::On` `AGENT=1`, `NO_COLOR=1`, `TERM=dumb`, `GIT_TERMINAL_PROMPT=0` and `cat` as the pager (`GIT_PAGER`, `PAGER`), with `FORCE_COLOR` and `CLICOLOR_FORCE` dropped, then a confined command's scratch `TMPDIR` last; its own session with no terminal, a deadline, a stop, stdout and stderr one pipe read on a thread, the group killed, then the rest of the session), `query.rs` (`query`: a short command the app runs for itself, `/diff`'s `git` and `doctor`'s shell, its stdout once it exited well; killed with all it started at its deadline (R10); `Unanswered` says why there is no answer), `sweep.rs` (every process of a session killed by its session id, on macOS listed into a table on the stack, on Linux the numbered entries of `/proc`; called from ordinary threads only), `leaders.rs` (the sessions running, listed from spawn until its command's run ends, for `kill_all` when the process must quit at once), `inherit.rs` (`streams_only`: what a command inherits of llx, its standard streams and no other descriptor, every one above stderr marked close-on-exec between fork and exec; for `bash` and monitors) and `output.rs` (what the model reads of the stream: a repeated line once with its count, a line past 2,000 characters shortened, 16,000 characters from the start and 64,000 from the end of a command that succeeded, 8,000 and 32,000 of one that failed) with `output/render.rs` (the bytes as a terminal shows them: escapes out, `\r` and backspace applied, a line past 64 KiB in pieces), `output/shown.rs` (the window as the model reads it once the command ended: the start, the cut and the command that reads it, the end) and `output/spill.rs` (the whole output, once something is left out, in `$TMPDIR/llx-output-<uid>/`: 0700, files 0600, 64 MiB a file, a day and 512 MiB in all at most).
  - `ask.rs`: `AskTool`, the agent's `ask`: one to three questions, each with its header and its options' previews, read leniently, answered through `Person`; the answers shown to the person as question → answer.
  - `testing.rs`: test-only: temporary directories, a descriptor open without close-on-exec (`stray`), and a gate that records what it is asked.
- `packages/providers/`: the models' providers, a package each, told who calls them (`App`).
  - `kit/`: what they share, with no port: `http.rs` (`Http`, a POST answered with a status and a body, a failure unsent only when it came before a byte went out; `Web` on the OS's TLS, its agent kept inside the kit, each post held to the request's deadline (ureq's per-request `timeout_global`), and `retry` sleeps no pause past it; `Web::get`, the catalog's GET, its answer read as a post's; forms and queries), `oauth.rs` (PKCE, random state, a pasted redirect, a token's claims, opening the system browser), `loopback.rs` (the sign-in callback on 127.0.0.1: route and `state` checked, `/cancel` to give way), `page.rs` (the browser's success and failure pages), `store.rs` (credential files, 0600; a pasted key read, a key masked for showing), `sse.rs` (server-sent events, read as an iterator), `cut.rs` (a call the output limit cut off: the string its JSON stopped in closed, B7), `retry.rs` (a request asked again when a wait may mend its answer, never one that went out unanswered unless the caller's `Resend` says once), `failure.rs` (a host's failure as Anthropic's and OpenRouter's clients report it: `ApiError`, whether a wait may mend a status, whether a failure says the account has nothing left to spend (`spent`: never asked again), the error a reply reports, a `null` one none, and what it says), `cache.rs` (the prompt cache's key: a hash of the words one conversation's requests start with).
  - `models/`: the model catalog, the one source of model facts (MODELS.md): `data/` is models.dev's own files for the popular providers (`scripts/models_sync.py` copies them from a clone), `build.rs` resolves them as models.dev does into its v2 shape (built in deflated, and read only when no fetched catalog has the provider asked for), `lib.rs` reads it (providers, chat and decision models, windows, levels and defaults, API addresses, `takes_marks`: the models that cache only at marked breakpoints; `switch.rs`: how a host's chat completions turn a model's thinking off where it takes a toggle of its own; `takes_lark`, which a fetched catalog answers from the built-in files, as models.dev's API does not publish it), `provider.rs` (a provider read as an index of raw JSON, each model decoded the first time it is asked for: a run decodes the few it uses), `source.rs` fetches models.dev's v2 API at most once an hour (ETag), through the kit's `Web::get`, and keeps it in `<config>/models.json` (`<config>`: llx's config directory, `~/.config/llx`), over the built-in files. `types.rs` is the catalog's types: a model as models.dev's v2 publishes it, and what its facts say (its price, its API's address); `build.rs` includes it by path and cuts the built-in files by it, as a fetched catalog is cut.
  - `local/`: the hosts the catalog does not know (A4's exception), of two kinds (`Kind`): the model servers on the person's own machine (`Local`) and any other host of chat completions the settings name (`Any`): `hosts.rs` (the hosts looked for: Ollama at `OLLAMA_HOST` or its default, LM Studio and llama.cpp's server at theirs, then those the settings name, one of a known host's name replacing it), `probe.rs` (`models`: what a host runs, from its `/v1/models`, embedding models left out, or the models the settings list, the host then not asked; a local one with the context each is loaded with as the host's own API says it: llama.cpp's `/props`, LM Studio's `/api/v0/models`, Ollama's `/api/ps`, unknown, 0, for a model not loaded, and a reply 8,192 tokens at most, a quarter of a small context; a host anywhere with the context and the reply's most the settings say, else the caller's own), `lib.rs` (`Host`, `Kind`, and `Get`, the GET a host is asked with, 2 s at most for a local one and 5 s for one anywhere, faked in tests).
  - `openrouter/`: `chat.rs` (chat completions, tool calling; OpenRouter's `reasoning`, cost, prompt-cache marks and a `session_id` per conversation (its first words: its logs' sessions, and the host its cache is on), or `reasoning_effort` for any other OpenAI-compatible host, a server on the person's machine (`Wire::Local`) asked to stream with its usage (`stream_options`), what it read from its cache taken from llama.cpp's `timings`, sent a key only when it has one and waited for 30 minutes with no silence limit, and OpenAI's own API the prompt cache's key per conversation (the `session_id`'s) and the output limit as `max_completion_tokens`; OpenRouter asked to stream; a reply the host's filter withheld an error), `level.rs` (the level as each host takes it: OpenRouter's `reasoning`, `reasoning_effort` by name, or a host's own toggle for off, `Switch`; the output limit a level leaves room in), `carry.rs` (what a turn takes back to the model that wrote it: its reasoning, an answer given in chunks, each call's own extra, Gemini's thought signature), `stream.rs` (a streamed completion put back together as one sent whole: a cut call keeps what it wrote, an error midway is the answer), `system_one.rs` (the decision models), `mend.rs` (a request a host other than OpenRouter or OpenAI refused for a field it names: the field left out, or the reply's limit renamed to the one it asks for, or the cache marks taken off, asked again and remembered for the client's later requests), `client.rs` (OpenRouter, or any address the catalog gives; OpenRouter told the app, `HTTP-Referer` and `X-OpenRouter-Title`; the kit's `retry`: a timed-out request is not sent again, but a decision is, once), `auth.rs` (the OpenRouter key's variable, its credentials path and the PKCE sign-in; saving a key is `Provider::save_key`, for every provider).
  - `anthropic/`: the Messages API, Anthropic's own, where the catalog serves a model over it (`providers.rs` chooses it over chat completions, which there cache no prompt and ignore the level): `client.rs` (`Messages`: `x-api-key` and the API's version, the kit's `retry`, a stream that failed after its first words not sent again), `request.rs` (the body: the system prompt apart and marked for the cache, which marks the tools too, the conversation as alternating turns with each call's results right after it, the context, the previous request's last turn and the last turn marked; the level as `output_config.effort` with adaptive thinking, or a budget of thinking tokens for a model whose reasoning takes one (`Thinking`); a forced call sent as `auto`, as the current models refuse one; each tool's input streamed as it is written (`eager_input_streaming`), so a cut call arrives with what it wrote (B7); 64,000 tokens a reply at most, at every level; the turn sent back as it came, its signed thinking where it was, but what the API refused as bound to an earlier history), `stream.rs` (the streamed message put back together: a cut call's input kept as its text, B7), `chat.rs` (`ChatModel`, the reply as a completion: the usage with what the cache read and wrote, `written_tokens`; thinking refused as bound to a history that changed since sent again without it, once, and its signatures never sent again; a refusal or a reply past the window an error), and the test-only `testing.rs`.
  - `openai/`: OpenAI's Responses API, with a ChatGPT sign-in (the backend) or an API key: `auth.rs` (the OAuth flow: authorize, exchange, refresh), `tokens.rs` (the tokens, the account id from their claims, `openai.json`, no ID token kept; `Saved`, where a refresh keeps them), `responses.rs` (the chat port over the Responses API, streamed, signed by `responses/signin.rs` (the sign-in's tokens, refreshed) or a key; each conversation a session of its own at the backend (`session-id` and the prompt cache's key, from its first words), so sessions and agents reach their own cache and no one machine takes them all; its own clients (600 s, 300 s idle; the token endpoint's at 60 s, `auth::issuer`, which the sign-in's exchange uses too); refresh before expiry and once on 401, held to the request's deadline, a refresh that cannot be saved logged; a stream cut off sent once more), `responses/reply.rs` (a streamed reply read: its items, its usage; a content-filtered reply an error, one that failed for load before any word asked again), `responses/offer.rs` (the tools as the backend takes them: `apply_patch` a custom tool held to its Lark grammar where the catalog says the model takes one (`Texts`), else a function), `responses/route.rs` (sticky routing: the `x-codex-turn-state` a task's first reply names, kept by the session and `Request::task` and sent back with the task's later requests so they reach the machine that holds its cache), `responses/request.rs` (the request body: the conversation as input items, the tools, the level, the prompt cache's key), and the test-only `testing.rs` (tokens shaped as the issuer shapes them, an HTTP fake that answers from a script and records what was sent).
  - A new provider is a package here implementing `Chat` (and `Decider` where it has decision models) with a catalog, and one arm per `match` in `apps/server/src/providers.rs`.
- `packages/protocol`: what the interface and the server say to each other (ARCHITECTURE.md W1-W8), the seam's types only, no dependency at all: `event.rs` (`Event`: what happened in a session; a call's `Label` and `Outcome`), `asked.rs` (`Asked`: a question for the person, a choice's rows in optional `Group`s; `Reply`), `command.rs` (`Command`: what the interface asks of the server (`JobOutput`: what a job printed, sent back as `Event::JobOutput`), `Done`), `frame.rs` (`ToClient`, `ToServer`: every frame, values on channels, never encoded); `Offer`, what the server offers the interface as it starts (W3).

Time and memory grow with the text, whatever it is.
- `packages/session`: a history store: each session a JSON Lines file, `<id>.jsonl` (`journal.rs`: its header, then each task and each title as it came, appended by its one writer, which holds the file's lock (`File::try_lock`) for as long as it lives; a line a crash cut short left out when read), each id the second it started and a number its process counts up from one random draw, so none is given twice in a process.

- `skills/llx/SKILL.md`: the skill for any agent that takes skills (`npx skills add localixai/localix-cli`; in Claude Code the plugin the root's `.claude-plugin/marketplace.json` lists, `strict: false`, its entry the whole plugin), as agent-browser's is: what llx is and what each part is for, with examples to run as they are (the agent, scripts and CI with a workflow for the action, helpers, decide, and a search of the code by what it does as `rg` and `llx decide` make it), whose `allowed-tools` lets Claude Code run without asking, while the skill is active, `llx decide` and `llx exec --mode plan` with any arguments after them, `llx doctor`, and the guides it points at, `llx --help` and `llx exec --help` (nothing else: every other command goes by the person's permission settings; `scripts/checks/skill.sh` checks the frontmatter), and which ends with `llx exec --help` and `llx decide --help` as the binary prints them, written by `scripts/skill-help` after the marker line and checked by `suite/repo/skill.rs`.
- `docs/`: the guides (`usage`, `modes`, `tools`, `agents`, `ci`, `recipes`, `reference`, `compare`: the action beside other agents' actions), each a page of the site.
- `site/`: the website (Vite, React, TypeScript, built with npm; `prerender.mjs` writes each page as HTML, and `scripts/install.sh` at `/install`), its docs pages read from `docs/` and `examples/README.md`; published by `.github/workflows/site.yml`.
- `.github/workflows/`: `ci.yml` (each step a `scripts/check --only NAME`; `check`, `size` and `site` on the project's runners, `scripts/runner/`, a fork's pull request on GitHub's; `action` on GitHub's), `release.yml` (a `vX.Y.Z` tag: the tests, the archives (macOS, Linux x86_64 and arm64), the release, its image; the action's major tag moved), `site.yml`.
- At the root: `LAYOUT.md` (this map), `README.md`, `CHANGELOG.md`, `MODELS.md`, `RELEASING.md`, `CONTRIBUTING.md`, `SECURITY.md`; `.config/nextest.toml` (one retry, a test ended after three 60 s periods); `.gitleaksignore` (the `secrets` check's findings known to be fake, by fingerprint).
- `scripts/`: `check` (the checks' one entry point, AGENTS.md) with `checks/`: `plan.sh` and `plan.awk` (the checks a change needs, from its paths), `run.sh` (each check's command), `tree.sh` (the changed paths, the tree's fingerprint and stamp), `tools.sh` (the pinned linters), `mdlinks.sh` (Markdown's relative links), `skill.sh` (the skill as an agent reads it: every `skills/NAME/SKILL.md`, and every skill the plugin's manifest lists, opens with a frontmatter that parses as YAML, with `name` its directory's, a `description` of at most 1,024 characters and `allowed-tools`; `.claude-plugin/marketplace.json` parses, and each plugin's `skills` path holds a SKILL.md), `check_test.sh` (their tests); `hooks/` (git's `pre-commit` and `pre-push`, Claude Code's `claude-stop`, wired in `.claude/settings.json`), `setup` (the git hooks installed), `ci-docker` (CI's jobs in Docker: each job's `run` steps read from `ci.yml`, in `docker/Dockerfile`'s image of the runner, as `runner` with passwordless sudo, as GitHub's runners are); `runner/` (the project's own CI runners: their image, an ephemeral runner per job, the compose file and systemd unit that run them, and how to set a machine up); the release scripts (`dist.sh`, `release-notes.sh`, `install.sh` (the one way to install a release: curl, checked against `SHA256SUMS`), `image/Dockerfile` (the release's image on ghcr.io, from its Linux archives)), `coverage.sh`, `skill-help` (the skill's reference written from the help llx prints), `models_sync.py` (models.dev's files from a clone into the catalog's `data/`; with no clone named, or a path that is not one, its usage line and exit 2, `data/` untouched).
- `benchmark/`: llx as an agent (and Codex to compare), scored by tests written in advance (`benchmark/README.md`): `tasks/` (each a Bun project the agent is given, `project/`, and its reference, `ref/`), `run.ts` (Bun alone: each agent on the task, the fixed files put back, `bun test` the score; `--check` checks a task, `--history` remakes the history) with `lib/` (`task.ts` the task's copy, compare and score, `agents.ts` how llx and Codex are started and what their logs say, `price.ts` the cost from llx's catalog, `report.ts` the summary and the history), `results/` (a run's `run.json`, `summary.md` and every log, compressed) and `HISTORY.md`. The harness's own tests (`lib/agents.test.ts`) run with `bun test ./benchmark/lib`, no agent and no network.
