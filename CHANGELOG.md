# Changelog

## Unreleased

- Initial release.
- A task's time limit (`--timeout`) now also ends a model request in flight: each request carries the time left as a deadline and the HTTP client stops waiting at it, no longer after the provider's own 10 minutes; a retry sleeps no pause past it.
- Every run ends with the `result` tool, with or without `--schema`: `achieved`, a `summary`, and `blocked_by` when the goal is not reached. A `result` not achieved that names no block is a progress report, not an end: it is refused with one line (the task goes on, what is left to do is no block) as often as it comes, and never counted as a schema mismatch, which ended the run as not achieved after two. The refusal no longer asks for the call again: told to, the model called it again with a blocker it made up, and one task-tracker run in six ended with work left; Codex, with no such tool, ended none. Text alone no longer ends a task: a progress note sent as a reply is answered with a line that only `result` ends it, each time, until it does or `--max-turns`/`--timeout` run out. `--json` schema 6: the `unstated` status is gone (a run ends `achieved`, `not_achieved`, `exhausted`, `error` or `interrupted`); the `RESULT:` line is gone from the prompt and the agent.
- Tools: a patch is applied whole or not at all (a failed write puts back the files written before it) and every failure says no file was changed; lines only added after an `@@` anchor go below it; `bash` keeps 8,000 characters of a stream's start and 32,000 of its end, cut at lines; the read-only scratch `TMPDIR` holds with a client's environment; Linux's read-only sandbox needs Landlock ABI 3; the Windows leftovers are gone.
- The system prompt is written for work on its own (CI, scripts): autonomy and persistence, updates beside the calls and one final message when the work is done (the `commentary` and `final` channels the models are trained on), the context, and what is never done; how to work is left to the model and the tools' descriptions. It no longer asks for a RESULT line: a model that wrote its progress as an answer stopped with work left.
- Failed calls no longer take the model's tools away: after three turns of failed calls it was told to answer with what it had. A failure goes back with its reason, and the model tries another way; a run is bounded by `--max-turns` and `--timeout`.
- ChatGPT: a reply withheld by the content filter is an error, not an empty answer; a stream cut or timed out is sent once more; a refreshed sign-in that cannot be saved is logged as a warning, and an `invalid_grant` refresh says to `/login` again.
- An HTTP request that fails after it went out (a connection closed before the answer) counts as unanswered, not unsent, so it is not sent again where that could be billed twice.
- Which OpenRouter models take prompt-cache breakpoints is the model catalog's (`ModelEntry::marks`), no longer a list of id prefixes in the provider.
- `--budget USD` (and the action's `budget` input) bounds what one task may spend, beside `--max-turns` and `--timeout`: the first limit reached ends the task with exit 2. It counts the cost the provider reports (OpenRouter does, a ChatGPT sign-in does not).
- `bash` keeps about 40,000 characters of each stream (some 10,000 tokens, as Codex does), where it kept 10,000: a test file or a build log reaches the model whole, not cut in the middle. A tool result keeps up to 90,000 characters.
- With a ChatGPT sign-in, `apply_patch` is offered again as a tool held to its grammar for the models that take one: a fetched catalog (models.dev's v2 API, which does not publish it) had turned it into a JSON function for every OpenAI model, and patches came back cut short or malformed.
- A patch whose lines are not found in the file says so with the file's nearest lines, numbered: the next patch needs no read first.
- When the conversation is trimmed for the model's limit, the text of old patches goes as other large arguments do.
- llx runs on macOS and Linux: the code that was meant for Windows, which no release built, is gone, and `scripts/dist.sh` builds no Windows archive.
- `--timeout` also stops a command or an agent that is running when the time is up (it is killed as a stop kills it), not only at the next model turn; the run ends `exhausted` as before.
- A panic that reaches the top of the process ends it with exit 3 and one line (`llx: internal error: ... (see the log)`), not a trace and exit 101.
- SIGHUP stops the task as SIGTERM does; a second signal quits at once after killing every command and monitor started, which no longer outlive the process.
- At most 8 agents work at once, and a closed agent that has stopped is let go of when the next one starts.
- Fixed: an `--allow` or `--deny` rule with many wildcards no longer takes exponential time on a long command or path that does not match.
- Fixed: a number key pressed on a choice with no options no longer ends the interface.
- Markdown's ~~strikethrough~~ shows struck through; `/usage` says the cost once, the time on a line of its own.
- A task has no turn limit unless `--max-turns` gives one (it was 50, and cut long tasks off while they were still fixing what failed); `--timeout` bounds it. The GitHub Action's `max-turns` has no default either.
- OpenRouter requests carry prompt-cache marks only for the models that take them (Anthropic, Gemini, Qwen); OpenAI, DeepSeek, Grok and the rest cache on their own and are sent plain messages.
- With a ChatGPT sign-in, the model's reasoning goes back with each next request, sealed, as the backend keeps nothing: the model no longer thinks the task through again at every turn. After `/model` switched, another model's reasoning stays out.
- Five tools: `bash`, `apply_patch`, `ask`, `agents` and `jobs`. The model reads, searches and runs the checks in the shell, as a person at a terminal does (`cat`, `sed -n`, `rg`; the context names the runtimes the shell has: `python3`, `node`, `bun`), and changes files with `apply_patch`, a patch of free text: a custom tool held to its grammar where the ChatGPT backend takes one, a function elsewhere. In a read-only mode a patch is refused. `read` and `exec` are gone. `/rewind` goes back in the conversation only: the files stay as they are.
- `plan` is read-only for real: its commands run without asking in the system's sandbox (Seatbelt on macOS, Landlock and seccomp on Linux), where writing a file, opening a socket or reaching another program fails; where no sandbox can be set up, a command is refused. A mode of your own takes `"read_only": true` in `settings.json`.
- Beside Codex on the same model (GPT-6 Luna, medium reasoning), every run at once, building a task tracker's API from its tests: llx scores 195 of 199 (the median of 6 runs) to Codex's 197 (of 3), at the same cost, and every run ends with `result` ([benchmarks/task-tracker/runs](benchmarks/task-tracker/runs)).
- With a ChatGPT sign-in, a task's later requests go back to the machine that holds its prompt cache (the routing token its first reply names): fewer requests read the whole conversation afresh.
- With a ChatGPT sign-in, each session and each agent is a session of its own at the backend (`session-id` and the prompt cache's key, from the conversation's first words), where all of a process's sessions shared one: their requests spread over the backend's machines instead of crowding one.
- The model starts another agent only for a large, separate part of the work, not for what a few reads and commands settle: an agent reads it all again, at a second cost.
- `evals/arena/`: one reference task run by llx and by Codex on the same model, judged by hidden tests.
